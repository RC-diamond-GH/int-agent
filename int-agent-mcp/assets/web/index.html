RESPONSIBILITIES, NOT LIVE SESSIONS

角色与协作边界

静态职责图 · 非在线成员统计
01

用户

定义目标与验收；回原生 Worker / Reviewer 窗口回答问题和权限确认。

02

大管家 / Steward

与用户讨论、通过 MCP 分派任务和读取证据。daemon 不追踪其会话、进程、在线人数或每个任务的创建者身份。

03

控制器 / daemon

持久化任务，通过私有 tmux 管理运行实例，并按版本证据推进交付门禁；不是实现任务的 Agent。

04

Worker

在独立 worktree 实现任务，持有独立运行与会话；提问记录与进程是否存活需要分别核对。

05

Reviewer

在固定 base / head 的独立 worktree 审查，提交结构化报告；运行结束不等于报告通过。

06

GitHub

保存 PR 与实际 CI / 合并证据。看板展示 daemon 记录，不自行实时查询远端，也不授权合并。

职责关系：用户 ↔ 大管家 → MCP → 控制器 → Worker / Reviewer；控制器 ↔ GitHub。此图不是实际创建链或等待依赖图；具体创建者与任意任务依赖未被追踪，只有明确的修复关联、待答记录及事件可作为关系证据。

观测不是操作，也不是完整现场。

原生工具权限弹窗不在看板观测范围内；没有 pending 记录不代表没有等待。ask 记录可能早于弹窗或在崩溃后残留。请在对应私有 tmux 窗口核实并处理。网页只提供经过引用处理的接入命令复制，不执行终端、不回答问题、不恢复、不取消、不合并。

自动观测约每 5 秒一次；请求串行，不重叠。
